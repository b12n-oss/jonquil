- This form vs the file on disk, vs git HEAD and vs the last Run: the compare commands for just the top-level form around the caret, its differences in the Locations list and Take working on it alone. The form is matched in the other version by its first two elements, such as `defn f` (a `defmethod` by its dispatch value too), and its place among forms that share them.
- Find Usages in Project tells same-named symbols apart: it works out which var the symbol at the caret names from the file's `ns` form, its own definitions and the local bindings, and lists only that var's places at first. The **Other vars** and **Unresolved** check boxes, each with its count, bring back another var's or a local's places and the ones a file can't decide (`:refer :all`, `:use`, a name a macro defines).
- Quick Doc for This Var: on a var result in the console, the right-click menu and the palette print that var's doc into the console as comment lines, below the result.
- `jolt metrics`, `jolt metrics:edn`, `jolt metrics:json` and `jolt metrics:html` report code metrics with jolt-metrics (report only, never a gate), configured in `.jolt-metrics.edn`. The HTML report is one self-contained page, written to `target/metrics.html` by default. Since jolt-metrics v0.4.0 the queue ranks a function by how much of the code depends on it, and the report adds unusual commits and files.
- ClojureDocs examples in JVM Clojure's full doc are runnable: each has Run in Interactions and Copy to Definitions. The example's `user=>` prompts and printed results are dropped first. Run always uses the `user` namespace (the console says `; in user` when the prompt is elsewhere, and the prompt doesn't move), honours plugin before-run vetoes and refuses while the console is busy. Copy puts the example after the top-level form at the caret, or inside a `(comment ...)` block when the caret is in one, as one undo step. The buttons are mouse-only.
- Last session's replay (Jolt and JVM Clojure): Jonquil records what each project evaluated, the console offers it at open and at Open Folder, and Open last session's replay in the palette puts it in a new tab as files, definitions and `#_`-skipped other forms. Nothing runs until you Run. Forget last session clears it, and `:remember-session? false` turns recording off. Running the replay carries the forms still behind `#_` into the next replay. The record is plain text in `replays/` beside the settings file, owner-only.
- The Up/Down history survives a dialect switch, and is saved with the replay record.
- A project's `.jonquil.edn` can set `:remember-session?` for itself: `false` keeps that project's evaluations and history off disk, `true` records them even when `settings.edn` turns the replay off. A value that isn't true or false is reported on the console and ignored.
- Named layouts: Save the layout keeps whether the file tree and a right-hand panel show, the tree's width and the editor/console split, named after what shows; Use layout: name in the palette brings one back. Kept in the settings file.
- Compare with the file on disk, or with git HEAD: the tab's differences from that version go in the Locations list, and Take the other version here puts that version's lines back for the difference at the caret, as one undo step.
- Compare with tab: the palette lists every other open tab, and comparing with one puts the differences in the Locations list the same way, saved or not. Take the other version here reads that tab as it is now.
- Compare with the last Run: the tab against the text its last whole Run sent, when that Run ended without an error, so the Locations list shows what changed since the running code was loaded.
- The status bar names the keys that act on the symbol at the caret (`Ctrl+Q doc · F12 jump · Shift+F6 rename`), from the live keymap. Show what keys do at the caret, in the palette, turns it off for the session.
- The Processes panel (Cmd/Ctrl+Alt+8, or Show the processes in the palette): the fibers your program spawns with `jolt.fibers/spawn`, each with its state and age, and Interrupt, Kill and Forget finished. Jonquil starts watching `spawn` the first time the panel opens, since Jolt keeps no list of live fibers. In process and in the Jolt child.
- `!` at the Interactions prompt runs a palette command by its words: `!list every key binding` and Return runs it, words that match several list them, and the line goes into the history.
- Count how often each line runs (Jolt, v0.8.24 or later): a palette toggle turns on Jolt's `jolt.profile` line counters, and after a Run of a saved file the gutter shows each line's hits beside it (`6`, `1.2k`). Each Run counts itself alone, an edit hides the counts until the next Run, and Clear line counts zeroes them. In process and in the Jolt child.
- An open tab follows its file when it changes on disk, for example when an agent edits it with its own tools. A tab with no unsaved edits reloads, keeping its caret, as one undo step, so Cmd/Ctrl+Z brings the old text back. A tab with unsaved edits keeps them and takes the disk text as its saved version, so Save writes over it knowingly. Messages logs each case. Plugin tabs' reload after a Revert or Accept is one undo step too.
- The Messages panel (Cmd/Ctrl+Alt+7): one log of what happened in the background. Every MCP tool call an agent makes gets a row named by the agent's client ("Claude Code replaced the text of core.clj"), and so does an open tab's file changing on disk, which is how agents' own edit tools show up. Agents attaching and leaving, an attached runtime's connection dropping, and runtime starts are logged as well. Read-only calls and status-bar lines are logged too but hidden until ticked. The status bar counts unread messages, and Enter on a row jumps to its tab or opens an evaluation's code and result.
- Switching panels: the command palette lists **Switch to panel: name** for each right-hand panel you've had open, the last one seen first, and Cmd/Ctrl+Alt+1 to 6 focus the Inspector, Source, Locations, Frames, Trace or Plugins panel when it's showing and otherwise bring it back or open it: Frames, Trace and Plugins ask for what they show now, and the Inspector, Source and Locations come back with what they showed, or say on the status bar what fills them.
- ClojureScript in the browser: a tab left over from an earlier session can no longer reload itself into a new session that lands on its recycled port. The page URL carries a per-window token, and a page request bearing another window's token gets a script-free page saying "This tab belongs to an older Jonquil session. Close this tab." The same window's tab still reloads itself across restarts, and a hand-typed bare URL still serves the page.
- ClojureScript on node: `read-line` works the way it does on Jolt. The status bar says `Waiting for input`, the next console line answers the read instead of being evaluated, Cmd/Ctrl+D ends input for one read, and Stop frees a waiting read by restarting the process. The launcher relays Jonquil's lines into a FIFO in its own temp folder and the session defines `cljs.core/read-line` to read it, so plain `(read-line)` compiles without warnings in any namespace. The browser target still has no stdin.
- `.jonquil.edn` `{:cljs {:target :browser :forward-console? false}}` keeps the browser page's `console.log` out of Jonquil's console, for debugging through devtools with real source links; `println` still arrives.
- Ctrl+Shift+F6 and Ctrl+Shift+F1 no longer trigger rename and quick doc; those chords are Shift-only.
- A browser tab whose server never comes back stops its keep-fresh ping after about an hour instead of polling the port forever, and a later port owner rejecting the ping can't keep the loop alive.
- ClojureScript in the browser: the tab reloads itself after Stop or Reset on Run, once the new process is listening, instead of asking you to reload it by hand.
- ClojureScript: a Run or REPL entry no longer waits out an in-flight completion fetch or quick-doc lookup (up to ~2 s against a browser tab that just closed); the evaluation cancels it.
- ClojureScript completion (node and browser) offers every loaded namespace's publics, asked from the compiler's analyzer on the first completion after an evaluation, spelled the way the buffer's ns form can use them: `str/upper-case` behind an alias, bare names for the current namespace and anything referred, and full `some.ns/name` once the prefix contains a `.` or `/`.
- Guide screenshots for ClojureScript on node, in the browser and attached to a shadow-cljs build, and for the nREPL dialect attached to babashka. Four new `jolt docs:shots` scenes (`cljs-node`, `cljs-browser`, `cljs-shadow`, `nrepl-bb`) take them against the real runtimes, each in its own temp project, and stop whatever they started afterwards.
- ClojureScript in the browser: `js/console.log`, `info`, `warn`, `error` and `debug` print to Jonquil's console as well as the browser's devtools.
- ClojureScript in the browser (experimental): `.jonquil.edn {:cljs {:target :browser}}` in a project without `shadow-cljs.edn` runs the launched ClojureScript in a browser tab instead of node. The first Run opens the page in the default browser (or through `JONQUIL_OPEN_URL`) and waits up to 60 seconds for it; Stop and Reset on Run restart ClojureScript and ask you to reload the tab at the same URL. Both listeners are loopback-only (ClojureScript's browser REPL server would otherwise bind every interface), and unauthenticated like the node runtime.
- ClojureScript on node (experimental): a `.cljs` file outside a shadow-cljs project, or a loose one, now runs in its own ClojureScript process on node instead of explaining that there is nothing to attach to. Jonquil starts it on the first Run with the Clojure CLI and `node`, evaluates every top-level form, streams output, keeps the session across a JavaScript exception, and refuses input that ends inside a form. Stop and Reset on Run restart it, and Reset on Run starts unticked there, since a restart takes a few seconds. Both of its local listeners are unauthenticated and bound to `127.0.0.1` (the launcher patches ClojureScript's node script at run time, which otherwise listens on every interface). A project with `shadow-cljs.edn` still attaches, and `.jonquil.edn {:runtime :launch}` or `{:runtime :attach}` chooses. `jolt test:cljs-node` runs a live suite, and the self-test gained a tenth window.
- `.jonquil.edn :auto-require` works for Jolt projects too, in and out of process: the listed namespaces load before the first evaluation (out of process, again after the Jolt runtime restarts), so the first line at the prompt can call into them.
- F12 on a definition in one of your project's files opens it in a tab, ready to edit, instead of the read-only source panel; Cmd/Ctrl+[ goes back to where you pressed F12 (the last 50 jumps). Library code and files outside the project still open in the panel.
- Jump to definition (F12) leaves the buffer for Jolt running out of process: a function from another file in the project opens in its tab, and one from a jar dependency in the source panel, on its definition. Functions built into Jolt have no source file, so they show their documentation as before.
- A project kept in process (`{:runtime :in-process}`) can require its own namespaces: its `deps.edn` `:paths` are Jolt's source folders there now, so F12 also opens those files. Its `:deps` libraries load there too, fetched on the first evaluation that needs them, off the window's thread.
- With Jolt in process, F12 on a function another tab's Run defined opens that tab's file on the definition, once the file is saved, instead of showing the docs.
- An nREPL dialect: `.jonquil.edn {:dialect :nrepl :nrepl {:port 1667}}` attaches to any nREPL server you started (babashka, a non-JVM Clojure, one on another host with `:host`). Features follow the ops the server offers, and the console names the ones it lacks. Checked live against babashka (`jolt test:bb`).
- Quick docs ask cider's `info` when a server has no `lookup` op (Basilisp has only `info`), for the nREPL dialect and JVM Clojure alike.
- `jolt test:nightly` runs the live nREPL suite against Jolt's nightly build, downloaded, checked against its `.sha256` and cached under `~/.cache/jonquil/jolt-nightly`, so a Jolt change that breaks Jonquil shows up before a release.
- `jolt test:basilisp` runs the nREPL dialect against a real `basilisp nrepl-server`.
- JVM Clojure asks cider's `complete` for completions when the server has no builtin `completions` (a pre-1.0 nREPL with cider-nrepl), instead of offering only the buffer's names.
- `read-line` and `read` work for Jolt running out of process: Jonquil's own nREPL middleware in the Jolt child asks for each line at the prompt, Cmd/Ctrl+D ends input for that read, and Stop frees a waiting read. A plain nREPL server (the fallback when jolt-lang/nrepl can't be fetched), or a child that couldn't load Jonquil's middleware, still has no stdin.
- The inspector (Cmd/Ctrl+I) works for Jolt running out of process: Jonquil loads its inspector code into the Jolt child as nREPL middleware, written under `~/.cache/jonquil/nrepl-middleware`, so stepping through a value leaves `*1`, `*2` and `*3` alone, on a plain nREPL server too.
- ClojureScript dialect (experimental): Jonquil attaches to a running shadow-cljs nREPL server, selects the build from `.jonquil.edn` or `shadow-cljs.edn`, and Runs a `.cljs` buffer in the JS runtime that has the build loaded; see the ClojureScript section of the using guide. `jolt smoke:cljs` drives it against a live app.

### Fixed

<summary><strong>32 entries</strong></summary>

- Two presses of the line counts toggle at once, or a line counts toggle at the same moment as the debug-mode toggle, no longer lose one. Each toggle read Jolt's instrumentation mode and then set it, so both could read the old mode and the status bar could disagree with the runtime. Every read-then-set of the mode now holds one lock, in process and in the Jolt child.
- A plugin's `p/eval!` of code that throws reports the error's own message again on newer Jolt, where `load-string` wraps a runtime throw in a CompilerException ("Syntax error macroexpanding at (1:1).") the way JVM Clojure does. The wrapper is unwrapped only when it marks the throw as raised while running, so a cause the code gave its own throw stays hidden.
- ClojureScript on node: when the launcher made its `read-line` pipe but couldn't open it, the whole session failed to start (the launcher exited before its ready line). It now opens the pipe up front, so that failure takes the same path as a failed `mkfifo`: the session runs, and `read-line` throws "read-line isn't available" with one console line saying so.
- jank: Stop returns at once instead of holding the window while jank dies. ClojureScript on node: output the program prints while quick docs are fetched goes to the console instead of the doc popup.
- ClojureScript on node: Stop returns at once instead of holding the window while the process dies, and output the program prints after an evaluation answered (a `setTimeout`) reaches the console. The child's run folder, and jank's, is created owner-only with an unguessable name.
- Typing in the rename popover no longer triggers window shortcuts: Cmd/Ctrl+W, Cmd/Ctrl+T, F5 and the rest go to the entry, so a rename can't close or switch the tab or Run it. Escape still closes the popover.
- Quick doc and the completion preview recover from a lookup that failed once, instead of showing nothing for that name until the next evaluation, and a lookup that a Run overtakes no longer brings back the doc from before the Run.
- When out-of-process Jolt can't start, the console's message says where the child's log is.
- Jump to definition (F12) follows bindings from `for`/`doseq` `:let` modifiers and `letfn` function parameters, and lands on the enclosing `#(` for `%` arguments, instead of answering "No definition found".
- Completion, quick-doc and rename popovers follow the caret while the editor scrolls, and hide once the caret scrolls out of view, instead of staying put over unrelated text.
- ClojureScript in the browser: an evaluation sent after the page's tab closed fails within a couple of seconds, naming the URL to reload, instead of waiting until Stop.
- ClojureScript: when the session setup fails, the message names the child's log and the log is kept; before, the message sometimes named a log that was already deleted.
- ClojureScript on node: node picks its own loopback port and tells the launcher, so another program can no longer take the port between the launcher choosing it and node binding it.
- `jolt smoke:binary` records its six precondition checks on passing runs too, so its SUMMARY total no longer differs between passing and failing runs, and every parking helper of the self-test harness now refuses to run on the GTK thread, as `call-gtk` always did.
- A GTK self-test row that outlives its per-row timeout is abandoned: its body can no longer act into the next row through the harness helpers.
- The editor group of the GTK self-test exits 1 when the app quits before its last row, as the window group already did, and the find bar's Escape-while-running row can no longer pass without opening the bar.
- The GTK self-test presses Stop when a row leaves an evaluation running (one that threw before its own Stop), so a single failing row no longer fails every row after it with "Evaluation already in progress".
- Logs and run folders a failed start keeps for its error message, and what a killed child leaves behind, are deleted from the temp folder after a day instead of staying there for good. A folder a running child still uses is left alone.
- When out-of-process Jolt falls back to a plain nREPL server, the logs of the attempts it gave up on are deleted instead of left in the temp folder.
- An evaluation error that arrives with no message reads "Error: evaluation failed" rather than a bare "Error: ".
- Jump to definition keeps working on Jolt newer than v0.8.23, which records a required namespace's file by its classpath name (`demo/util.clj`) rather than a path: Jonquil now looks that name up on the classpath, in process and out.
- The completion list is as tall as its names, up to eight rows, rather than always eight; a name the buffer defines is labelled `buffer`, not `user`; the quick-doc popover fits its text, up to the width it always had; solarized's selected completion row is visible; and the status bar no longer runs into the window's right edge.
- The nREPL dialect's error line against Basilisp shows the exception (`ZeroDivisionError: Fraction(1, 0)`) or a compile error's message, not `Traceback (most recent call last):`.
- The nREPL dialect's stdin notice no longer says every read waits until Stop: Basilisp's `read-line` reads the server's own terminal.
- Open With offers Jonquil for `.cljs` files too, on macOS (the app's document types) and Linux (the `text/x-clojure` MIME globs), now that there's a ClojureScript dialect.
- JVM Clojure: output from another thread while `read-line` waits no longer takes the console out of input mode.
- Find and replace: Return on a focused Replace or Replace All button presses it, instead of moving to the next match.
- Format All and Format Selection keep the caret on the same code and scroll it into view.
- The inspector's `d` does nothing while the panel's actions are disabled, and a runtime switch that hides a focused inspector or source panel moves focus to the editor.
- F12 inside the source panel on a definition in the window's own file moves the window's caret there, instead of loading that file into the panel.
- `--mcp-attach DIR` follows a listening window after Open Folder re-roots it.
- Old `~/.cache/jonquil/nrepl-middleware` folders from other Jonquil versions are pruned after a day unused.
