# Changelog

All notable changes to this project are documented here, starting from
the open-source preparation work (2026-10-17). The guide describes
everything that shipped before that.

## [Unreleased]

### Added

- The rest of Calva's paredit set, 27 more structural editing commands: drag a form backward and forward, transpose, join, split, convolute, wrap in `#{}` and `""`, rewrap, kill the form before the caret, kill to the end or start of the line or the list, splice while killing forward or backward, expand and shrink the selection, select forward and backward, and four more moves. Twelve have Calva's keys (Alt+Up and Down to drag, Ctrl+Alt+T, Ctrl+Shift+J, Ctrl+Shift+C, Ctrl+Alt+Backspace and others). The rest are in Edit > Structure and the palette without a key, where Calva's key is a two-step one or already does something else. A new guide page, Structural editing, shows every one of the 42 commands with a before and an after, and a test runs each row against the real command.
- Menus: File, Edit, View, Search, Run, Debug, Tools and Help, in the menu bar on a Mac and behind a ☰ button at the end of the toolbar on Linux. They list 146 commands, each with the key the live key map gives it, and each item runs its command the way the palette does. The menus are rebuilt when the key map changes, so a key you set in Preferences or `keys.edn`, or one a plugin adds, shows in them at once. A key belongs to whatever has the focus: while a text box or the console has it, the menus don't take a key meant for it.
- Structural editing: slurp and barf in both directions, raise, splice, wrap in `()`, `[]` or `{}`, kill and copy a form, and moves forward, backward, up and down by a form. Slurp, barf, kill, splice and wrap have Calva's keys (Ctrl+Alt+Right and Left, with Shift for the backward pair, Ctrl+Shift+Delete, Ctrl+Alt+S, and Ctrl+Alt+Shift+P, S and C); the rest are in the command palette, and Preferences can give any of them a key. They are extra commands: arrow keys, Backspace and Delete work as before, and Parinfer works with or without them: with it on, the indentation follows the bracket a command moved, in every mode. Key bindings can now name the arrow keys, Home, End, Backspace and Delete.
- A Preferences window, on Cmd/Ctrl+comma and as Open Preferences in the command palette. Its Keys tab lists every command with its key and where the key comes from, narrows the list as you type, and records a new key when you click a row's key and press one. It asks before taking a key another command has, refuses a key that types unless it holds a modifier other than Shift, so a binding can't replace typing, and has Reset this key and Open keys.edn. It writes `keys.edn`, and asks first when that file holds comments of yours. Closes #14.
- Your own key bindings. `keys.edn`, next to `settings.edn`, holds `:window` and `:editor` bindings that are tried before a plugin's and before Jonquil's own, and a `:remove` list that drops a binding you don't want. Open your key bindings file in the command palette opens it, with a commented starter file the first time. Saving it in Jonquil reloads it, and so does Reload your key bindings. An entry Jonquil can't use is skipped and named in the console, and the rest load. That includes a binding on a key that types (a letter, a digit, Return, Space, punctuation) with no modifier but Shift, since it would run each time you typed the key. Until now the keys were fixed when Jonquil was built, so the downloaded app had no way to change one short of a plugin.

### Changed

- A key binding that holds Alt now works on a Mac for every letter, digit and named punctuation key, in the shipped keys, in `keys.edn` and when the Keys tab records one. Option changes the character a key sends, so the key is matched by its position, which until now was done only for F, L, P and the digits and needed `:physical? true` on the binding. The positions are a US keyboard's, so on another layout such a binding fires on the key that sits where the letter does on a US one. Save, Save As, the palette and the Parinfer key no longer fire when Alt (or, for Parinfer, Shift) is also held, which on Linux had taken Ctrl+Alt+S and its neighbours.
- Work now merges into a `develop` branch, and `develop` merges into `main` when the work on it is ready. CI runs on pushes to both, both have the same branch rule, and the contributing pages say to open pull requests against `develop`.

### Fixed

- The fake nREPL servers the tests use now stop for certain: `stop!` waits for the accept loop to end before it closes the listening socket. While that loop was still inside `accept` the port went on taking connections after `stop!` had returned, which failed `fake-drops-and-stops-test` on about one macOS CI run in four. Under CPU load the port took a connection after 25 of 600 stops before the change and after none of 600 with it.
- `gtk_text_buffer_insert_interactive` now gets its text as a copy the garbage collector can't move, like the four calls fixed in 0.2.1. Only two console rows of the GUI self-tests call it, so the app wasn't affected, but those rows could now and then insert other text than they meant to.

## [0.2.1] - 2026-11-14

### Changed

- CI has one required check, `ci ok`. `.github/workflows/ci.yml` calls the lint, docs, attribution and Linux workflows as lanes, adds `jolt test` and `jolt test:nrepl` on an Apple Silicon macOS runner, and its last job fails unless every lane passed. The Linux GUI self-tests now count toward a merge.
- `jolt metrics:gate` now covers `dev/` and `ci/` as well as `src/` and `test/`, so the fake servers, the screenshot script and the self-test harness meet the same limits as the app's code. The fourteen findings there were split into named steps and smaller files, with the self-tests' rows, order and results unchanged.

### Fixed

- Text put into an editor, the console or an entry could now and then reach GTK as freed memory. Jonquil passed it as a string argument, which is a buffer the garbage collector may move, and GTK calls Jonquil's own handlers before it has copied the text. A collection in that moment crashed Jonquil ("invalid memory reference"). The Linux self-tests also hit GTK's abort on text that wasn't valid UTF-8, in the rows where plugins load, and a test with a forced collection read back other text than it had inserted. The four calls that insert text now hand GTK a copy the collector can't move.
- On Linux, closing a popover with Escape while one of its buttons had the focus left the focus on the editor's scroll container, so typing didn't reach the editor. GTK moves focus out of a closed popover later on X11 than on macOS, and Jonquil's step that hands focus back ran before that. It now takes the focus when it is still inside the popover that closed.
- The Linux GUI self-tests run with a window manager, and four rows that failed there now pass: one was the focus fix above, one needed an active window, one checked for "Cmd" in a list of bindings that says "Ctrl" on Linux, and one read a selection that X11 drops when no real key press came with it.

## [0.2.0] - 2026-11-14

### Added

- A `jonquil` command for your terminal. On macOS, Install the jonquil command for your terminal in the command palette links it to the app you are running: `jonquil` opens the current folder in a new window, `jonquil <folder>` does the same for that folder and reopens the tabs it had last time, `jonquil <file>` opens the file as a tab in the Jonquil that is running, and the prompt comes back at once. The link goes in `/usr/local/bin` when Jonquil can write there and in `~/.local/bin` otherwise, with no password prompt, and Remove the jonquil command from your terminal takes it out. On Linux, `jolt app:install` links `~/.local/bin/jonquil` to the installed binary.
- Six more themes: Tokyo Night, Catppuccin Mocha, Catppuccin Latte, One Dark, Kanagawa and Rosé Pine, with the same contrast floors and "Use theme" palette entries as the other ten. One Dark's comment grey is a little lighter than the original's, since the original falls under Jonquil's contrast floor. Credits are in `NOTICE`.
- `jonquil --version` prints the version and exits without opening a window, and the command palette has a Show Jonquil's version entry that prints it to the console. The build tasks bake the version into the binary from `JONQUIL_VERSION` if it is set, else `git describe`, so set it for a build, not for a run. A binary built by a bare `jolt build` bakes nothing and reports the checkout it runs in, or `dev`. A run from source asks git about its checkout each time.
- Linux CI: `.github/workflows/linux.yml` builds the Linux image (`dev/linux/Dockerfile`) for amd64 and runs `jolt linux:test` and `jolt linux:selftest` on every push to `main` and every pull request. Six GUI rows fail on Linux today (issue #9) and are listed in `ci/linux-known-failures.txt`: the GUI job passes while only those fail, fails on any other row, and uploads the log.
- Six popular themes: Gruvbox Dark, Gruvbox Light, Dracula, Nord, Zenburn and Monokai, taking each original's colours (credited in `NOTICE`) with Jonquil's own token mapping and the same contrast floors as the first four. The command palette now has a "Use theme: <name>" entry for each theme and for auto, so you can pick one by name. Cmd/Ctrl+Shift+M still cycles through them all.
- Issue forms for bug reports (asking for the Jonquil and Jolt versions, how you run it, the OS and the dialect) and feature requests, a `SECURITY.md` that sends vulnerability reports to GitHub's private reporting, and a `.github/CONTRIBUTING.md` that points at the Contributing guide and `AI_POLICY.md`.

### Fixed

- The MCP server reports the version that is running in its `initialize` reply. It said 0.1.0 whatever the build.
- A folder opened with Finder's Open With, or dropped on the Dock icon, while Jonquil isn't running now comes up with that folder's own tabs from last time. macOS hands the folder over after the window has started, and by then Jonquil had queued the tabs of the project used last, so those opened beside the new folder's file tree. A folder that reaches a window nobody has used yet, one clean Untitled tab, opens its tabs too.
- `jolt gtk:selftest` and `jolt test:nrepl` no longer need a jolt-lang/nrepl checkout. Without one, the nREPL window self-test used to record one failing row and stop before its summary, and one live test failed. Both now get the middleware the way the app does: from a checkout when there is one, else as the pinned git dependency, which needs `git` and a network the first time.
- Out of process, a Jolt Run now starts in `user`, as it does in process. It used to start in whatever namespace the last console entry had left the child's session in, so a buffer with no `ns` form put its vars there. A Run that Stop or an error ended also left the prompt where it was before the Run, and the vars it had defined couldn't be reached from the console by their plain names. The prompt now moves to the buffer's namespace when the child has it by then, and to `user` otherwise.
- When a file size limit stops your login shell during the PATH lookup, the console note now says so ("your login shell stopped at a file size limit"), where it used to say only "failed". On Linux the lookup sets such a limit itself. If the shell's output already holds a complete PATH, that PATH is still used.
- On Linux, a login shell that prints without end is now stopped by a file size limit while Jonquil looks up your PATH. The lookup already stopped the shell once its output passed 1 MB, by checking the size every 100 ms. On a GitHub Linux runner the first check took 219 seconds, and the shell wrote 90 GB in that time. The cause isn't known yet, so the kernel's limit now bounds the output whether or not the check runs in time.
- The notarize helper's test checks the file mode with GNU `stat` on Linux, so `jolt test` passes there too.
- The README and Getting started point at the notarized 0.1.0 download, the Jolt notes say which features need v0.8.24 (the first release with `jolt.debug` and `jolt.profile`) instead of "not yet in a release", the release build lists `pkgconf` and the Xcode Command Line Tools, and the README's test count is today's.
